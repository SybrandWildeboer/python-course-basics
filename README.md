# Python, SQL & Git

An eight session course for someone who has never written a line of code, built around one
dataset from start to finish. Eight two-hour sessions, one to one, with two to four hours of
homework in between.

Slides, notebooks, exercises, solutions and homework all live in this repository.

## Start here

```bash
git clone https://github.com/SybrandWildeboer/python-course-basics.git
cd python-course-basics
python3 serve.py
```

That opens the course index in your browser, which links to every session.

## How the work is organised

**Notebooks are where the work happens.** Each session has a `notebooks/` folder:

- `*-exercise.ipynb` and `*-homework.ipynb` are yours to fill in
- `*-solved.ipynb` are the answers, for after you have tried

Open them in VS Code, or run `jupyter lab` from this folder.

**Everything also exists as a plain `.py` script**, in `demos/`, `exercises/` and
`homework/`. That is deliberate. A notebook is for exploring; a script is for running. Seeing
both is how the difference makes sense, and session 8 is about turning one into the other.
Anything interactive, like the session 2 guessing game, is a script only, because `input()`
is awkward in a notebook.

```
slides/                 one deck per session, the course index, and the course pages:
                        start, install, troubleshooting, cheatsheets, dataset,
                        instructor notes and project template
sessions/session-NN/
    notebooks/          where you work
    demos/              the same material as scripts
    exercises/          script versions of the live exercises
    solutions/          worked answers
    homework/           homework, with answers in homework/solutions/
    README.md           run sheet and notes for whoever is teaching
data/                   the dataset: CSVs, a messy version, a SQLite database
my-work/                your scratch space
project/                the project template, which becomes your project in session 8
tools/                  scripts that check the course materials
```

## The dataset

One dataset carries the whole course: a personal music listening log of 2,183 plays across 40
artists and two years. It appears in four shapes.

| Shape | Where | Used in |
|---|---|---|
| Clean CSVs | `data/clean/` | sessions 4, 6, 7 |
| SQLite database, three tables | `data/music.db` | sessions 5, 6 |
| Deliberately messy CSV | `data/messy/` | session 6 |
| Everything above | | session 8 |

It is generated by a seeded standard-library script, so the numbers on the slides always
match the numbers on your machine. If you ever break it:

```bash
python3 data/scripts/build_dataset.py
```

## The eight sessions

| # | Session | Core skill |
|---|---|---|
| 1 | Setup and first contact | Environment, notebooks, variables, types, f-strings |
| 2 | Control flow | if/else, loops, reading error messages |
| 3 | Functions | def, return versus print, scope |
| 4 | Lists, dictionaries, files, and Git | Data structures, CSV in and out, commits, pushing to your own repo |
| 5 | SQL: foundations and joins | SELECT, WHERE, GROUP BY, HAVING, joins, and how a join makes your totals wrong |
| 6 | pandas, basic and advanced | DataFrames, groupby, merge, cleaning a messy file, dates and reshaping |
| 7 | Data visualization | matplotlib, choosing a chart, honest axes, small multiples, makeovers |
| 8 | The project, pair programming | Pipeline script, virtual environment, tests, and where to go next |

## Checking the materials

If you change anything, one command tells you whether it still holds together. On Windows
type `python`, on macOS `python3`.

```bash
python tools/check_all.py         # everything, a few minutes
python tools/check_all.py --fast  # skip running the notebooks and scripts
```

It runs the checks below, then runs every script under `sessions/` and `project/`, the
session 8 tests with pytest, and makes sure nothing was written outside the gitignored
`output/` folders. Scripts that ask for input are skipped, and it says so. You can also run
any one check on its own:

```bash
python3 tools/check_slides.py     # every slide fits, no overflow, notes present
python3 tools/check_sql.py        # every query runs, and returns the row count claimed
python3 tools/nbtool.py check     # notebooks are valid and carry no saved output
python3 tools/nbtool.py run       # every notebook still runs top to bottom
```

`check_slides.py`, `nbtool.py run` and the tests need a couple of extras. Without them,
`check_all.py` reports those checks as skipped rather than failed:

```bash
pip install playwright nbformat nbclient ipykernel pytest
playwright install chromium
```
