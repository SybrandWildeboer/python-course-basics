0:30 · how we work

You drive, I navigate

The driver

Has the keyboard. Types, and says out loud what they are about to do and why.

The navigator

Watches the bigger picture: is this the must? Did we run it? Asks questions rather than dictating keys.

Swap about every twenty minutes, so both of us stay awake. You drive most of the time: it is your project.

◆ The rhythm
  1. Pick the next stage from your notebook
  2. Make it a function that returns
  3. Call it from main(), which prints one line
  4. python pipeline.py
  5. Commit when it runs

When: FileNotFoundError from another folder

Paths that work from any folder

Path(__file__).resolve()is
.parentproject, the folder the file is in
.parent.parentthe repository root

A relative path counts from the terminal

"data/my_export.csv" works only when the terminal is in the right folder. From anywhere else: FileNotFoundError, though the file is fine.

__file__ counts from the script

Where this file lives, which never changes. Build every path from it, and the folder you run from stops mattering.

Not in a notebook: there is no file being run, so __file__ is a NameError.

Show it breaking first: a relative path, run from the repo root (works) and from project/ (fails). Then the __file__ version from both. demos/where_am_i.py prints both meanings of "here" side by side.

When: importing the pipeline runs everything

A program when you run it, a toolbox when you import it

demos/name_main.py
demos/import_name_main.py

Importing a file runs it. Only the if stops main() running on import, which is what lets explore.ipynb import the pipeline.

Run both demos. The surprise is that the top-level print runs on import: that is the evidence that importing executes the file, and why the two lines at the bottom matter.

When: No module named 'pandas', or "why a venv?"

requirements.txt in git, .venv/ never

A venv is a folder with its own Python and its own packages, for this project only. Nothing installed here can break anything else, and the list rebuilds it anywhere.

SymptomFix
No module named 'pandas'Not active in this terminal: activate it
"Running scripts is disabled"The execution policy, once: see the set-up slide
pip install fails on matplotlibPython 3.13 or newer: use 3.12
VS Code uses another PythonBottom right: pick the .venv one
.venv/ in git status.gitignore is missing it
A new packagepip install it, add it with its version

matplotlib 3.9.0 has no ready-made installer for Python 3.13 or newer, so pip tries to build it from source and fails. Command Prompt activates with .venv\Scripts\activate.bat, Git Bash with source .venv/Scripts/activate.

When: a bare except, or a missing file

Catch the error you expect, in the outer layer

A bare except: catches typos too

A NameError becomes "the file was empty", and the crash comes three functions later as a KeyError that says nothing about files.

Functions that calculate return, and let errors travel. Only the outer layer prints, and decides what to do about errors.
