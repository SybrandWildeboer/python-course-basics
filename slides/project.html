Project template · sessions 10 to 12

Your project

The project/ folder is where the final project lives. It already runs: out of the box it answers one question about the course's music data. You start by changing something that works, not by staring at an empty file.

load → clean → analyse → save pandas and matplotlib its own virtual environment

What is in it

Five files, and two folders that appear when you use it

project/
    README.md            what it is, how to run it, how to make it yours
    requirements.txt     pandas==2.3.1 and matplotlib==3.9.0
    pipeline.py          load -> clean -> analyse -> save, and main()
    notebooks/
        explore.ipynb    where you look at the data first
    data/
        README.md        your input data goes in this folder
    output/              made by the pipeline: summary.csv and chart.png
    .venv/               made by you, once: the project's own packages
FileWhat it does
pipeline.py The session 10 genre pipeline, with a shorter clean that is easier to rewrite. One function per stage: load, clean, analyse, save_csv, save_chart, check, and main to run them in order. Only main prints. The seven places you are meant to change are marked MAKE IT YOURS.
README.md The question, how to run it on Windows and macOS, the eight steps to make it yours, and what the data could not tell you. By session 12 it describes your project instead.
requirements.txt The packages, with exact versions, so anyone can rebuild the same environment.
notebooks/explore.ipynb Imports pipeline.py and runs its own load, clean and analyse, so you look at exactly what the script sees. It finds project/ wherever you opened it from. Open it in VS Code.
data/README.md Where your input file goes, and three rules: never edit the raw file by hand, keep its original name and date, and it is not committed.

Run it

The first time: make the virtual environment

A virtual environment is a private set of packages for this project only. Nothing you install in it can break anything else, and the versions are the ones in requirements.txt. You make it once. Open a terminal in the repository folder.

Windows (PowerShell)

cd project
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt

macOS

cd project
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

When it is active, the prompt starts with (.venv), and python and pip mean the project's own copies on both systems.

If PowerShell says running scripts is disabled, run this once, then activate again:

Set-ExecutionPolicy -Scope CurrentUser RemoteSigned

Every time after that

Activate the environment, then run the pipeline. From inside project/:

.venv\Scripts\Activate.ps1        # Windows
source .venv/bin/activate         # macOS
python pipeline.py

You should see:

Which genre do I spend most of my listening time on?
  loaded    2223 rows from plays_messy.csv
  cleaned   2183 rows
  wrote   output/summary.csv
  wrote   output/chart.png

Every path in pipeline.py is built from the location of the file itself, so python project/pipeline.py from the repository folder works too. deactivate switches the environment off again; closing the terminal does the same.

The answer, in output/summary.csv: Electronic, with 2,753.2 of 8,608.0 minutes, 32.0%. The chart's title states that answer. The total is lower than the database's 8,980.4 because 94 plays in the messy file lost their minutes, and the pipeline leaves them missing rather than guessing.

Make it yours

One stage at a time, and run the whole pipeline after each change

A pipeline that ran five minutes ago is easy to fix. One that has not run since this morning is not. The steps, in the order project/README.md gives them:

  1. Data. Put your file in project/data/ and point INPUT at the top of pipeline.py at it, for example INPUT = PROJECT / "data" / "my_export.csv". Change QUESTION to your question.
  2. Look. Run notebooks/explore.ipynb and write down every problem you find.
  3. Load. Fix load first if it fails: a semicolon needs sep=";", JSON needs pd.read_json. Excel needs pd.read_excel and the openpyxl package, which is not in requirements.txt; saving the sheet as CSV avoids it.
  4. Clean. Rewrite clean for your problems, one at a time. Put each decision in its docstring, because each one changes the answer.
  5. Analyse. Rewrite analyse to answer your question. It returns a table, prints nothing, and ends with .reset_index(), because save_csv writes without the index.
  6. Save. Change the two column names and the title in save_chart. The title states the answer.
  7. Check. Keep at least one check that compares a total in the written file with the same total worked out from the cleaned data.
  8. README. Your question, where the data came from, how to run it, and what the data could not tell you.

If you add a package, install it with the environment active and add it to requirements.txt with its version. pip freeze lists what is installed. For tests in session 12 that means python -m pip install pytest, then pytest in requirements.txt.

What git ignores

PathIgnored?Why
project/.venv/YesA few hundred megabytes of packages built for your computer and your Python. Useless on anyone else's machine. requirements.txt goes in git instead.
project/output/YesAnything the pipeline writes can be made again with one command.
project/data/*Yes, all but data/README.mdYour own spending, messages or listening history do not belong on GitHub, and a Spotify export contains IP addresses. Write in your project README where the data comes from and how to get it again; that sentence goes in git instead of the file.
pipeline.py, README.md, requirements.txt, notebooks/NoThese are the project. Commit them, small and often.

Check it, do not trust it

The rules are in the repository's root .gitignore. Run git status after making the environment and after adding your data file: neither should appear in the list. If your data is small and not private, you can choose to commit it so the project runs for anyone who clones it; git add -f adds an ignored file on purpose.

Commit notebooks without their output: python tools/nbtool.py strip project removes it (python3 on macOS).
