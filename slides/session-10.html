Part one

From notebook to script

The same code, in a shape you can run again next month with one command.

The reason

A notebook is for exploring. A script is for running.

What a notebook does to you, eventually

  • Order: every cell leans on the one before. Run them out of order and you get a different answer, or a baffling error
  • Hidden state: delete threshold = 5 and the cell using it still runs, until tomorrow's restart
  • Repetition: next month's file means running twelve cells by hand, in the right order, again

What a script gives you

  • It always runs top to bottom, in a fresh Python
  • It runs from one command, so next month costs nothing
  • Same input, same output, every time, on any machine
  • Another file, or a notebook, can import its functions
◆

The saved notebook is not the notebook you ran. Restart and Run All is the only honest test of one. Remember the repetitive task from your own week in session 1? A script is how it stops being repetitive.

Notebook 01 has the hidden-state demo: two cells, delete the first, the second still works. Show it if the idea does not land from the slide.

Part two

Virtual environments

One private set of packages per project, so nothing you install can break anything else.

The problem

One Python for everything stops working

◆

So far this course has used the Python you installed in session 1, with everything in it. That is fine for learning. A project you want to run again next year gets its own environment, and a list of exactly what is in it.

Keep the why short. The point lands properly the first time a pip install for one thing breaks another, and he has not had that yet. The concrete benefit today: the project's versions are written down and can be rebuilt anywhere.

Do it now · in project/

Create it once, activate it every time

Windows · PowerShell
macOS · Terminal

Active means (.venv) at the start of the prompt. Then python and pip are the project's own, on both systems. deactivate, or closing the terminal, switches it off.

▲

"Running scripts is disabled" on Windows? Once: Set-ExecutionPolicy -Scope CurrentUser RemoteSigned

Do this on his laptop, now. The execution policy error is the usual Windows snag, and meeting it alone at home is miserable. Command Prompt uses .venv\Scripts\activate.bat; Git Bash uses source .venv/Scripts/activate.

The classic follow-up: a new terminal, no (.venv), and ModuleNotFoundError for pandas. The fix is activating, not installing.

What goes in git

requirements.txt in, .venv/ out

Why pin the versions

==2.3.1 means this exact version. Next year, pandas will have changed; your project will still install what it was written for.

Why .venv/ never goes in git

Hundreds of megabytes, built for your computer and your Python. Useless anywhere else. The .gitignore from session 5 already has it.

The list goes in git, the folder never does. Anyone can rebuild the folder from the list with one command, including you on a new laptop.

Have him run git status after creating the venv and see that .venv does not appear. That is the proof the gitignore works, and it closes the loop on session 5.

pip freeze lists everything, including the packages pandas pulled in. For a small project, listing only the packages you import, pinned, is easier to read.

How the two work together

Explore in the notebook, keep it in the pipeline

  1. Look in explore.ipynb. It imports pipeline.py, so it sees exactly what the script sees.
  2. Try a fix or a calculation in a scratch cell until it works.
  3. Move it into the right stage of pipeline.py, with its decision in the docstring.
  4. Run python pipeline.py. If it breaks, you changed one thing, so you know where.
  5. Commit when it runs.

The notebook imports the pipeline; it never copies it. Two copies of the cleaning drift apart within a week, and then the chart and the notebook disagree.

This is the working rhythm for the next two sessions. The README for the course said session 10 is about turning a notebook into a script; this slide is the habit that keeps them as one thing afterwards.
