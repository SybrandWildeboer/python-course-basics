The three placesSession 5

PlaceWhat is thereMoves on with
Working folderThe files as you are editing themgit add
Staging areaWhat will go into the next commitgit commit
HistoryCommits: saved snapshots with a messagegit push
GitHubA copy of your history, somewhere elsegit pull brings it back

git status tells you which place your work is in, and usually suggests the command you want next. Run it constantly.

The loop you will run a thousand timesSession 5

git status                     # where is everything?
git add path/to/file.py        # stage one file
git add .                      # stage everything that changed
git commit -m "Answer the session 4 questions"
git push                       # send it to your repo on GitHub
git log --oneline              # the history, one line per commit
git log -3                     # just the last three

A good message says what the commit does, in a few words. Small commits, often: they are what makes history and review possible.

Seeing what changedSession 5

git diff                  # changes you have NOT staged yet
git diff --staged         # changes you HAVE staged
git diff HEAD~1           # what changed since the previous commit
git show HEAD             # the most recent commit in full
git show HEAD~3:file.py   # how a file looked three commits ago

- lines were removed, + lines added; a changed line shows as both. VS Code's Source Control panel shows the same thing side by side.

Setting up

Once per machineSession 5

git config --global user.name "Your Name"
git config --global user.email "you@example.com"
git config --global init.defaultBranch main
git config --global pull.rebase false
git config --list                  # check it took

Without a name and email, git refuses to commit.

Your own repo on GitHubSession 5

git remote -v                          # where does this copy point?
git remote rename origin course        # keep the course repo, as "course"
git remote add origin https://github.com/YOUR-NAME/python-course.git
git push -u origin main                # the first push, once

git pull                               # your own work, from another machine
git pull course main                   # updates to the course

A remote is a nickname for a URL. You cannot push to the course repo, so you add your own as origin.

Signing in to GitHubSession 5

gh auth login        # GitHub CLI: answer four questions, approve in the browser

GitHub does not accept your password for git. Without gh, make a personal access token on github.com (Settings, Developer settings, Personal access tokens) and paste it when git asks for a password. Save it in a password manager: you cannot view it again.

Branches and trouble

BranchesSession 5

git switch -c add-readme     # create a branch and move onto it
git branch                   # list branches, * marks where you are
# ... edit, add, commit as normal ...
git switch main              # back to main
git merge add-readme         # bring the branch's work into main
git branch -d add-readme     # delete the label; the commits stay
git push

A branch is a label on a line of commits. Work on one branch is invisible on the other until you merge.

Getting out of troubleSession 5

You want toType
Throw away changes to one filegit restore path/to/file.py
Unstage something added by mistakegit restore --staged file.py
Undo a commit by adding an opposite onegit revert <commit>
See how a file looked earliergit show HEAD~3:file.py
Work out what is going ongit status, then git log --oneline

Once something is committed it is very hard to lose. If you are in a mess: stop, run git status, and read it out. Do not delete the folder and start again. git reset --hard is left out on purpose: it really does throw work away.

A merge conflictSession 5

<<<<<<< HEAD
the line as it is on your branch
=======
the line as it is on the branch you are merging
>>>>>>> add-readme

Git stops and marks the file. Edit it to the version you want, delete the three marker lines, then git add the file and git commit. git status lists the files still in conflict.

What not to commitSession 5 Session 10

Commit what a human wrote. Ignore what a machine generated, anything enormous, and anything secret. The repo's .gitignore already covers output/, .venv/, __pycache__/ and .ipynb_checkpoints/.

python tools/nbtool.py strip     # remove saved notebook output before committing
python tools/nbtool.py check     # are the notebooks valid and output-free?

python3 on macOS. A password pushed once is public forever, even if the next commit deletes it: the history keeps it.
