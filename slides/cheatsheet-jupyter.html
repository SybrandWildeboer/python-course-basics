Showing valuesSession 1 Session 8

The last line of a cell shows its value without print(). Only the last line.

import pandas as pd

plays = pd.read_csv("data/clean/plays.csv")
plays.head()         # NOT shown: it is not the last line
plays.shape          # shown: (2183, 9)

Want several things from one cell? print() each one. In a script nothing shows without print(), last line or not.

The first cell of every course notebook finds the repository root and moves there, so paths like data/clean/plays.csv work. Run it first.

The one trap

Cells remember what you ran, not what is on screenSession 1 Session 10

Scroll up, change a cell, run it, and everything below is now out of date. Delete the line that made a variable, and the cells using it still run, until tomorrow. The number beside a cell, [1], [2], is the order things really ran in.

The fix, and it is the whole fix: Restart and Run All, from the toolbar. It clears everything and runs from the top, in order.

If a notebook cannot run cleanly from top to bottom, it is not finished, however good the output looks.

A cell that will not stopSession 1 Session 2

A cell showing [*] is still running. Stop it with the square interrupt button in the toolbar, the notebook version of Ctrl C in a terminal.

If that does not work, Restart the kernel. It throws away every variable, but it always works. Then run the cells again from the top.

The usual cause is a while loop whose condition never changes. Something inside the loop has to move it towards false.

Kernels

In VS CodeSession 1 Session 10

The kernel is the Python that runs the notebook. Packages have to be installed into that Python, or the import fails.

  • Top right of the notebook, Select Kernel, then Python Environments, and pick your Python 3.12.
  • If it asks for ipykernel, let VS Code install it.
  • For project/notebooks/explore.ipynb, from session 10, pick the .venv Python.
  • No module named 'pandas' in a notebook usually means the kernel is a different Python from the one you installed into.

Notebooks and git

Strip the output before you commitSession 5

A .ipynb is JSON: your code, your prose, and the output of every cell. So diffs are hard to read, saved output makes files big, and every run changes the run numbers even when the code did not change.

python tools/nbtool.py check     # valid, and no saved output?
python tools/nbtool.py strip     # remove saved output and run numbers
python tools/nbtool.py run       # does every notebook still run?

Windows; python3 on macOS. Each one takes a folder to narrow it down, as in python tools/nbtool.py strip sessions/session-05. .ipynb_checkpoints/ is already in .gitignore. sessions/session-05/notebooks/01-notebooks-and-git.ipynb shows a real cell's JSON.

Import the script into the notebookSession 10 Session 11

Explore in the notebook, move the settled steps into project/pipeline.py, and import them back. This is the setup cell of project/notebooks/explore.ipynb, without its two print lines:

import importlib
import sys
from pathlib import Path

import pandas as pd

def find_project(start):
    """Return the folder holding pipeline.py, looking in start and above it."""
    for folder in [start, *start.parents]:
        if (folder / "pipeline.py").exists():
            return folder
        if (folder / "project" / "pipeline.py").exists():
            return folder / "project"
    raise FileNotFoundError(f"no pipeline.py found in or above {start}")


PROJECT = find_project(Path.cwd())

sys.path.insert(0, str(PROJECT))
import pipeline

importlib.reload(pipeline)      # pick up changes you made to pipeline.py since
raw = pipeline.load(pipeline.INPUT)
print(raw.shape)                # (2223, 9): the messy file
data = pipeline.clean(raw)
print(data.shape)               # (2183, 9)

The import runs nothing you did not ask for, because pipeline.py only does work inside main(), behind if __name__ == "__main__":. Change load and clean in pipeline.py, not in the notebook, and run the setup cell again. It is also how you debug a script: import the failing function, call it on real data, and look at what comes back.
