When something breaks

The errors you will actually hit

And the fixes. The messages on this page are the real text, copied from running the mistake on purpose, with long paths shortened. Find the last line of your error, then find it here.

Read the last line first Then the line number Then the fix

The habit that solves most of these

Python prints a traceback: a wall of text that ends in one line saying what went wrong. Go straight to that last line. It names the kind of problem and gives a short description. Then look at the line number just above it, which is where Python gave up and nearly always where the fix goes. The middle is the route your program took to get there.

Session 2 practises this in sessions/session-02/notebooks/02-errors-on-purpose.ipynb: open it in VS Code and break each cell yourself.

Still stuck after ten minutes? Send the code, the exact error text, and what you tried.

Setup and Python itself

Session 1

python is not recognized, or command not found

Windows 
The term 'python' is not recognized as the name of a cmdlet, ...

or, if Windows sends you to the Store instead:

Python was not found; run without arguments to install from the Microsoft Store, ...

Python is installed, but the terminal cannot find it. Almost always the "Add python.exe to PATH" box in the installer was left unticked.

  1. Close every terminal, including the ones in VS Code, and open a new one. PATH is only read when a terminal starts. This fixes it most of the time.
  2. If not, re-run the Python installer, choose Modify, and tick the option to add Python to the environment variables.
macOS 
zsh: command not found: python

On a Mac it is python3 and pip3. Type those. Once a virtual environment is active (session 10), plain python works too.

Any session

Two Pythons on one machine

Very common, and the root of the next three problems. Ask Python which one it is, and ask the system which ones it can see:

Windows 
python -c "import sys; print(sys.executable)"
where.exe python
macOS 
python3 -c "import sys; print(sys.executable)"
which -a python3

On the machine this course was written on, where.exe python lists four, and the first one (3.11) is the one that runs:

C:\Users\...\Programs\Python\Python311\python.exe
C:\Users\...\Programs\Python\Python312\python.exe
C:\Users\...\Microsoft\WindowsApps\python.exe
C:\Users\...\Python\bin\python.exe

That is not a problem in itself. It only bites when you install a package into one and run your code with another.

Any session

pip says it installed it, Python says it is not there

pip is a separate command, and it can belong to a different Python from python. Real output, same machine as above:

> python -m pip --version
pip 26.0.1 from ...\Python311\Lib\site-packages\pip (python 3.11)
> pip --version
pip 25.0.1 from ...\Python312\Lib\site-packages\pip (python 3.12)

So pip install pandas installs into 3.12, and python runs 3.11, which has never heard of it. The fix is to always install through the Python you run:

python -m pip install pandas       # Windows
python3 -m pip install pandas      # macOS

Inside an active virtual environment, pip and python are the same Python, so either spelling works there.

Session 1, and every notebook after

VS Code cannot find a kernel, or picks the wrong one

The kernel is the Python that runs the notebook. Top right of the notebook, click Select Kernel (or the Python version shown there), then Python Environments, and pick the Python you installed packages into.

If none are listed, or it says the kernel needs ipykernel, let VS Code install it, or do it yourself:

python -m pip install ipykernel    # Windows
python3 -m pip install ipykernel   # macOS

In project/ from session 10, pick the .venv Python as the kernel. VS Code will offer to install ipykernel into it the first time.

Sessions 8 to 12

ModuleNotFoundError: No module named 'pandas'

Traceback (most recent call last):
  File "<string>", line 1, in <module>
ModuleNotFoundError: No module named 'pandas'

pandas is not installed in the Python that ran this. It may well be installed in a different one. Three usual causes:

  • Never installed. python -m pip install pandas matplotlib (Windows) or python3 -m pip install pandas matplotlib (macOS).
  • The notebook kernel is a different Python. See the kernel above.
  • From session 10: the virtual environment is not active in this terminal. The fix is activating, not installing. See no (.venv) in the prompt.
macOS with Homebrew

error: externally-managed-environment

If python3 on your Mac came from Homebrew rather than python.org, pip refuses to install into it, to protect Homebrew's own packages. Either install Python from python.org as the install guide says, or work inside a virtual environment, where pip always works. Do not reach for --break-system-packages; it does what it says.

Errors in your code

Session 1, and forever

"But I fixed that!"

Python runs the file on disk, not what is on your screen. An unsaved file has a dot next to its name in the VS Code tab. Save with Ctrl S (Windows) or Cmd S (macOS), every time, before you run.

Sessions 1 and 2

SyntaxError that makes no sense

Python cannot even read the line. Look at that line and the one above it: the usual causes are a missing colon at the end of an if or for, or a missing quote or bracket on the line before.

If it still looks perfect, check the quotes. Code pasted from a chat app or a document can carry “curly quotes” instead of "straight quotes", and Python only accepts the straight ones. Retype them by hand.

Also common in sessions 2 and 6: = where you meant ==. One stores a value, two compare.

Session 2

IndentationError

  File "indent_error.py", line 3
    print("a long one")
    ^
IndentationError: expected an indented block after 'if' statement on line 2

In Python, indentation is grammar, not decoration. The body of an if, for, while or def must be indented, by four spaces. The nastiest version is a mix of tabs and spaces, because it looks fine on screen. By default VS Code types four spaces when you press Tab in a .py file, so deleting the indentation and retyping it fixes it.

Sessions 1 to 3

NameError: name '...' is not defined

NameError: name 'totl' is not defined. Did you mean: 'total'?

Python has never seen that name. Usually a typo, or capitals (Total and total are two different names), or a variable you meant to create earlier and did not. Python often suggests the name you meant.

Two versions that are not typos:

  • A variable made inside a function, used outside it (session 3). It only exists inside. Return it instead.
  • In a notebook, the cell that creates it has not been run yet in this session. Run the cells above, or Restart and Run All.
Sessions 1 and 4

TypeError: unsupported operand type(s) for -: 'int' and 'str'

TypeError: unsupported operand type(s) for -: 'int' and 'str'

You did arithmetic with text. input() always hands you text, even when the person types digits, and so does every value read from a CSV with the csv module. Convert first:

year = int(input("Birth year: "))
minutes = float(row["minutes_played"])
Session 3

TypeError: ... 'NoneType' and 'int'

10.0
Traceback (most recent call last):
  File "none_error.py", line 9, in <module>
    print(week + 10)
          ~~~~~^~~~
TypeError: unsupported operand type(s) for +: 'NoneType' and 'int'

None is what a function gives back when it does not return anything. The 10.0 at the top is the clue: the function printed its answer instead of returning it.

def total_minutes(minutes):
    total = 0
    for m in minutes:
        total = total + m
    print(total)        # shows it, then hands back None

week = total_minutes([3.5, 4.0, 2.5])
print(week + 10)

Change print(total) to return total. The same error appears when a return sits inside an if and some inputs never reach it, and after x = x.sort(), because sort() sorts in place and returns None.

Every notebook

A notebook that disagrees with itself

A notebook remembers what you ran, not what is on screen. Change a cell further up, and everything below is out of date. Delete the line that created a variable, and later cells still work, until you open the notebook tomorrow. The numbers beside the cells, [1], [2], show the order things actually ran in.

The fix is the whole fix: Restart and Run All, from the toolbar. If a notebook cannot run cleanly from top to bottom, it is not finished. A cell that runs forever is stopped with the square interrupt button.

Files and data

Session 4 onward

FileNotFoundError, for a file that is right there

Real output, running a session 4 demo from inside sessions/session-04:

  File "...\sessions\session-04\demos\files_and_csv.py", line 22, in <module>
    with open(PLAYS, encoding="utf-8") as f:
         ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
FileNotFoundError: [Errno 2] No such file or directory: 'data/clean/plays.csv'

The file is fine. A relative path like data/clean/plays.csv is counted from the folder the terminal is in, and Python is looking in the wrong one. First move, every time, is to print where it is looking from:

import os
print(os.getcwd())

Then run from the repo root:

cd path/to/python-course-basics
python sessions/session-04/demos/files_and_csv.py      # Windows
python3 sessions/session-04/demos/files_and_csv.py     # macOS

The other usual cause is opening a single file in VS Code instead of the repo folder, so the terminal starts somewhere else. Notebooks avoid all this: their first cell walks up to the repo root. From session 10, scripts build their paths from __file__ instead, and run from any folder.

Writing a file can fail the same way when the folder does not exist yet. os.makedirs("output", exist_ok=True) makes it first.

Sessions 4 and 8

KeyError: 'minute_played'

KeyError: 'minute_played'

That column name does not exist. Here the column is minutes_played. Look at the real names rather than guessing: rows[0].keys() with the csv module, df.columns in pandas. In session 9 the messy file calls that column 'minutes played ', with a space in the middle and another at the end, which is the same error in disguise.

Session 4, Windows

Salon Mécanique comes out as Salon MÃ©canique

The data files are UTF-8. Windows opens text files as something else unless told, so without encoding="utf-8" the é in one artist's name turns into Ã©, with no error at all. Other files fail louder, with a UnicodeDecodeError. Always pass it:

with open("data/clean/plays.csv", encoding="utf-8") as f:
Session 8

ValueError: The truth value of a Series is ambiguous

ValueError: The truth value of a Series is ambiguous. Use a.empty, a.bool(), a.item(), a.any() or a.all().

You used and or or to combine two pandas conditions. Use & and |, with brackets around each condition:

plays[(plays["minutes_played"] > 4) & (plays["device"] == "phone")]

Leaving out the brackets around an | inside an & gives no error and a wrong number. Name each condition on its own line first if in doubt.

Git and GitHub

Session 5

Author identity unknown

Author identity unknown

*** Please tell me who you are.

Run

  git config --global user.email "you@example.com"
  git config --global user.name "Your Name"

Git will not commit until it knows who you are. Run those two lines with your own name and email, once per machine, then commit again.

Session 5

git push asks for a password, then fails

GitHub stopped accepting account passwords for git years ago, so typing yours ends in Authentication failed. In order of preference:

  1. gh auth login, with the GitHub CLI. Four questions, approve in the browser, done. It sets up git's credentials too.
  2. A personal access token, made on github.com under Settings, Developer settings, Personal access tokens. Paste it when git asks for a password. You cannot view it again, so save it in a password manager.
  3. An SSH key. The grown-up answer, and the fiddliest to set up.
Session 5

Permission denied, or 403, when pushing

You cloned the course repo in session 1, so origin still points at the course, and you cannot push to it. Keep it under another name and add your own:

git remote -v
git remote rename origin course
git remote add origin https://github.com/YOUR-NAME/python-course.git
git push -u origin main

After that, git push goes to your repo and git pull course main collects course updates.

Session 5 onward

! [rejected] main -> main (fetch first)

 ! [rejected]        main -> main (fetch first)
error: failed to push some refs to '...'
hint: Updates were rejected because the remote contains work that you do
hint: not have locally. This is usually caused by another repository pushing
hint: to the same ref. You may want to first integrate the remote changes
hint: (e.g., 'git pull ...') before pushing again.

GitHub has commits you do not, usually from another machine or an edit on the website. Pull them in, then push:

git pull
git push

If it says (non-fast-forward) instead, after you amended a commit you had already pushed, the usual advice online is git push --force, which overwrites GitHub's history with yours. Do not. Amend freely until you push, never after; fix a pushed mistake with a new commit.

Session 5 stretch, or any pull

CONFLICT (content): Merge conflict in ...

Auto-merging songs.txt
CONFLICT (content): Merge conflict in songs.txt
Automatic merge failed; fix conflicts and then commit the result.

Both sides changed the same line, and git will not guess which one you want. It is not an error; it is git leaving a decision to you. git status lists the files. In each one, the disputed part is marked:

<<<<<<< HEAD
My favourite songs
=======
Songs I love
>>>>>>> new-title

Above ======= is your version, below it the incoming one. Edit the file so it says what you want, delete the three marker lines, then:

git add songs.txt
git commit --no-edit

Not sure? git merge --abort puts everything back exactly as it was before the merge.

Session 5 onward

A notebook full of saved output in git

A .ipynb file stores the output of every cell you ran. Commit it like that and a small notebook becomes a large one, and every run makes a new diff even when the code is the same. Before committing, check and strip:

python tools/nbtool.py check     # Windows; python3 on macOS
python tools/nbtool.py strip

check flags a notebook with a line like ! path: 3 cells have saved output (run: nbtool.py strip). strip removes the outputs and the run numbers from every notebook, or only the folders you name after it. Your code is untouched.

Environments and tools

Session 10, Windows

Activate.ps1 cannot be loaded because running scripts is disabled on this system

PowerShell blocks scripts by default, and activating a virtual environment is a script. Run this once, then activate again:

Set-ExecutionPolicy -Scope CurrentUser RemoteSigned

It only changes the setting for your own user. Command Prompt activates with .venv\Scripts\activate.bat instead, and Git Bash with source .venv/Scripts/activate.

Session 10 onward

No (.venv) at the start of the prompt

A new terminal starts without the environment. That is when No module named 'pandas' appears for a project that worked yesterday. Activate it again, from project/:

.venv\Scripts\Activate.ps1         # Windows
source .venv/bin/activate          # macOS

VS Code can also pick a different Python for the terminal and for the notebook kernel. The Python version in the bottom right of the window, and the kernel at the top right of a notebook, should both point at the .venv one for project/.

If .venv/ ever shows up in git status, do not commit it. The repo's .gitignore already lists it; check that the line is there.

Session 10

pip install -r requirements.txt fails while building matplotlib

project/requirements.txt pins matplotlib==3.9.0 and pandas==2.3.1. Ready-made installers for that matplotlib exist up to Python 3.12, and for that pandas up to 3.13. On a newer Python, pip falls back to building from source code, which needs a compiler, and fails with a long error.

The simplest fix is to make the environment with Python 3.12, if it is installed:

py -3.12 -m venv .venv          # Windows
python3.12 -m venv .venv        # macOS

Delete the broken .venv folder first. The other fix is to change the pins to versions that support your Python, and say so in the project README.

Session 12

pytest: command not found, or ModuleNotFoundError in a test

Either pytest is not installed in the active environment, or the test file is not next to the module it imports. Run it through Python, which settles the first, and name the folder:

python -m pip install pytest
python -m pytest sessions/session-12/solutions

Running python -m pytest from the repo root with no folder collects every test in the course, including the exercise starter that fails on purpose. And never call a file of your own statistics.py: it hides Python's own statistics module.

Any time

serve.py and the port

If port 8000 is busy, usually because the server is already running in another terminal, serve.py takes the next free one and tells you:

      http://localhost:8001/slides/index.html

  (port 8000 was busy, using 8001)

Use the address it prints. To stop the old one, find its terminal and press Ctrl C. If you want a particular port, pass it: python serve.py --port 9001. Only if twelve ports in a row are busy does it give up and ask you to pick one.

An edit that does not show up after a reload is almost always an unsaved file. The server tells the browser not to cache anything.
