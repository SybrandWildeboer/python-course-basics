Where to run itSession 6 Session 8

In DB Browser for SQLite: open data/music.db, Execute SQL tab, Ctrl Enter (Cmd Enter on a Mac) runs the query the cursor is in. From Python:

import sqlite3
import pandas as pd

con = sqlite3.connect("data/music.db")
print(con.execute("SELECT COUNT(*) FROM plays").fetchone())   # (2183,)
print(pd.read_sql("SELECT * FROM artists LIMIT 3", con))      # a DataFrame
con.close()

One table

SELECT and WHERESession 6

SELECT track_name, minutes_played     -- which columns
FROM plays                            -- from which table
WHERE minutes_played > 8;             -- which rows: 82

SELECT * FROM plays WHERE device = 'phone';          -- 1039 rows
SELECT * FROM plays WHERE played_at >= '2025-01-01'; -- 1061 rows

One = in SQL, and 'single quotes' for text. Double quotes mean a column name. Dates as YYYY-MM-DD text compare and sort correctly.

AND, OR, IN, BETWEEN, LIKESession 6

SELECT * FROM plays
WHERE (device = 'car' OR device = 'tablet')   -- bracket any mix
  AND minutes_played > 5;                     -- 107 rows

SELECT * FROM plays WHERE device IN ('car', 'tablet');   -- 284 rows
SELECT * FROM plays
WHERE played_at BETWEEN '2025-06-01' AND '2025-08-31';   -- 175, both ends in
SELECT artist_name FROM artists WHERE artist_name LIKE 'The %';  -- 5 rows

AND binds tighter than OR. In LIKE, % is any run of characters and _ exactly one.

NULLSession 6

SELECT artist_name FROM artists WHERE formed_year = NULL;   -- 0 rows, no warning
SELECT artist_name, formed_year, still_active FROM artists
WHERE formed_year IS NULL OR still_active IS NULL;          -- 3 rows
SELECT COUNT(*), COUNT(formed_year) FROM artists;           -- 40 | 38

NULL means unknown, not zero. Test it with IS NULL and IS NOT NULL. COUNT(column) and AVG skip NULLs.

ORDER BY, LIMIT, DISTINCTSession 6

SELECT track_name, minutes_played FROM plays
ORDER BY minutes_played DESC          -- ASC is the default
LIMIT 5;                              -- Paper Avenue 11.01 first

SELECT DISTINCT device FROM plays;              -- 5 values
SELECT COUNT(DISTINCT track_name) FROM plays;   -- 168

LIMIT without ORDER BY gives arbitrary rows, not the first of anything. Run DISTINCT on every text column of a new table.

AggregatesSession 6

SELECT COUNT(*)                      AS plays,
       ROUND(SUM(minutes_played), 1) AS total_min,
       ROUND(AVG(minutes_played), 2) AS avg_min,
       MAX(minutes_played)           AS longest,
       MIN(played_at)                AS first_day
FROM plays;                          -- 2183 | 8980.4 | 4.11 | 11.01 | 2024-01-01

AS names a result column. COUNT(*) counts rows; COUNT(col) counts non-NULL values.

GROUP BY and HAVINGSession 6

SELECT device,
       COUNT(*)                      AS plays,
       ROUND(AVG(minutes_played), 2) AS avg_min
FROM plays
WHERE played_at >= '2025-01-01'      -- rows, before grouping
GROUP BY device
HAVING COUNT(*) > 100                -- groups, after grouping
ORDER BY plays DESC;                 -- phone 479, laptop 261, speaker 174

The rule: every column in the SELECT is either in the GROUP BY or inside an aggregate. SQLite lets you break it and quietly picks a value.

The order it runs inSession 6

WrittenRuns
SELECT … FROM … WHERE … GROUP BY … HAVING … ORDER BY … LIMIT FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT

Why WHERE COUNT(*) > 100 fails (nothing is counted yet), and why an AS name works in ORDER BY but not in WHERE.

Dates, rates and whole numbersSession 6

SELECT strftime('%Y', played_at) AS year, COUNT(*) AS plays
FROM plays GROUP BY year;            -- 2024 1122 | 2025 1061

SELECT device,
       ROUND(100.0 * SUM(skipped) / COUNT(*), 1) AS skip_pct
FROM plays GROUP BY device ORDER BY skip_pct DESC;   -- speaker 14.0 first

SELECT 19 / 179, 100.0 * 19 / 179;   -- 0 | 10.61...

Whole number divided by whole number is a whole number in SQLite. Multiply by 100.0 first. substr(played_at, 1, 7) gives the month as 2025-04.

Two tables and more

JOINSession 7

SELECT p.played_at, a.artist_name, p.track_name
FROM plays AS p
JOIN artists AS a ON a.artist_id = p.artist_id
ORDER BY p.played_at
LIMIT 5;

SELECT artist_id, artist_name, track_name    -- same key name on both sides
FROM plays
JOIN artists USING (artist_id)
LIMIT 5;

Read ON as the matching rule. A column in both tables needs its prefix: artist_id alone is ambiguous column name. A plain JOIN is an inner join: rows with no match vanish.

LEFT JOINSession 7

SELECT a.artist_name, COUNT(p.play_id) AS plays   -- NOT COUNT(*)
FROM artists a
LEFT JOIN plays p USING (artist_id)
GROUP BY a.artist_id
ORDER BY plays
LIMIT 2;                         -- Iron Fernway 0, Gravel Choir 0

SELECT a.artist_name             -- only the unmatched ones
FROM artists a
LEFT JOIN plays p ON p.artist_id = a.artist_id
WHERE p.play_id IS NULL;         -- 2 rows

Every row of the left table survives, with NULLs where nothing matched. COUNT(*) would count that NULL row and say 1.

Fan-out: check the row countSession 7

SELECT COUNT(*), ROUND(SUM(minutes_played), 1)
FROM plays;                                      -- 2183 | 8980.4

SELECT COUNT(*), ROUND(SUM(p.minutes_played), 1)
FROM plays p
JOIN awards w ON w.artist_id = p.artist_id;      -- 2371 | 9732.1  wrong

An artist with three awards gets every play counted three times. No error. After any join, compare the row count with the one before. SUM(DISTINCT) is not the fix: it drops real plays that share a value.

The fix: aggregate first, with a CTESession 7

WITH per_artist AS (
    SELECT artist_id,
           COUNT(*)                      AS plays,
           ROUND(SUM(minutes_played), 1) AS minutes
    FROM plays
    GROUP BY artist_id
)
SELECT a.artist_name, s.plays, s.minutes, COUNT(w.award_id) AS awards
FROM per_artist s
JOIN artists a USING (artist_id)
LEFT JOIN awards w USING (artist_id)
GROUP BY a.artist_id
ORDER BY s.minutes DESC
LIMIT 3;    -- Glass Tram 229 1175.1 2 | DJ Kompas 215 1169.2 1 | Fjord & Flint 237 846.2 3

One row per artist before the awards join, so there is nothing to duplicate. The same thing works as a subquery in FROM ( … ) AS s; a CTE reads top to bottom instead of inside out.

COALESCE and viewsSession 7

SELECT a.artist_name, COALESCE(w.award_name, 'none') AS award
FROM artists a
LEFT JOIN awards w USING (artist_id)
WHERE a.artist_name = 'Iron Fernway';          -- Iron Fernway | none

CREATE VIEW artist_summary AS
SELECT a.artist_id, a.artist_name, COUNT(p.play_id) AS plays
FROM artists a LEFT JOIN plays p USING (artist_id)
GROUP BY a.artist_id;

SELECT artist_name FROM artist_summary WHERE plays = 0;   -- 2 rows
DROP VIEW artist_summary;

COALESCE(x, 0) is "x, or 0 if x is NULL". A view stores the query, not the data, so it is always current.
