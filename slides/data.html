The dataset · one listening log, four shapes

The listening log

One made-up but realistic music listening log carries the whole course: two years of plays, forty artists, and a few awards. The same data arrives as clean CSVs, as a database, and as a deliberately damaged export, so every new tool answers questions you have already answered with the last one.

2,183 plays 40 artists 33 awards 1 Jan 2024 to 31 Dec 2025 8,980.4 minutes in total

Why one dataset

Because then the numbers can be checked. Total minutes are 8,980.4 whether you add them up with a loop in session 4, SUM in session 6 or pandas in session 8. When a new tool gives a different number, something is wrong, and you know it straight away.

Three things in the tables are there on purpose

The gaps in artists are the three NULL values above. Session 6 needs real ones to teach IS NULL, and a lookup table always has a few. They are only in columns that are not copied into plays.csv, so the clean CSV stays complete.

Two artists are never played: Iron Fernway and Gravel Choir. Session 7 uses them to show what LEFT JOIN keeps and an inner join drops.

Awards are one-to-many. Join plays to awards and add up the minutes, and 8,980.4 becomes 9,732.1, because a play by an artist with three awards is counted three times. That wrong total is session 7's fan-out lesson, and it comes back in sessions 8 and 12.

The other two clean files match the database

artists.csv and awards.csv have the same columns and rows as their tables. One difference shows up in pandas: the gaps in formed_year and still_active are empty cells, so pandas reads those two columns as float64, not whole numbers. A column of integers with one missing value becomes a column of decimals. It surprises everybody once.

Worth knowing before you open it

NA is read as missing. Plain pd.read_csv turns the text NA into a missing value, so 49 countries quietly vanish before you have looked at anything. Session 9's load_messy reads the file with keep_default_na=False, so nothing is guessed and every decision is made in the cleaning, where you can see it.

One kind of damage never shows. damage also writes about 6% of the minutes with a thousands separator, but no play is longer than 11.01 minutes, so those values only come out with two decimals, like 4.20. The pipeline still handles a value like 1 234.50, for when real data has one.

What cleaning cannot recover: the 94 missing minutes (372.4 minutes, about 4% of the total) and the 69 missing devices. After cleaning, the file has 2,183 rows again, and seven of the nine columns match plays.csv in every row. The other two are exactly the information destroyed before the file reached you.

How it is made, and how to rebuild it

One seeded script, standard library only

data/scripts/build_dataset.py makes all five files from one random seed (20260101), so the same numbers come out on every machine, and the numbers on the slides match yours. It uses only Python's standard library, because it has to work in session 1, before anything is installed.

If you change or break a data file, run this from the repository folder. It overwrites all five files with the originals.

python data/scripts/build_dataset.py      # Windows
python3 data/scripts/build_dataset.py     # macOS

On Windows you should see:

wrote data\clean\artists.csv  (40 rows)
wrote data\clean\awards.csv  (33 rows)
wrote data\clean\plays.csv  (2183 rows)
wrote data\messy\plays_messy.csv  (2223 rows)
wrote data\music.db  (40 artists, 2183 plays, 33 awards)

On macOS the paths use /. Either way the CSV files come out identical, byte for byte, to the ones in the repository, and the database holds exactly the same rows.
