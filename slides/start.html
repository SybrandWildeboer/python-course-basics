How this course works

What is in the repo, how to get it running, where your work goes, and what a normal week looks like. Read it once at the start. Come back when something feels out of place.

12 sessions 2 hours each, one to one 2 to 4 hours homework a week One dataset all the way through

Get it running

Three commands, once you have Python and Git

If you do not have Python, VS Code and Git yet, do the install guide first. Session 1 does it with you, so there is no need to do it alone beforehand.

Then, in a terminal, in a folder you will find again (no spaces or accents in the path):

git clone https://github.com/SybrandWildeboer/python-course-basics.git
cd python-course-basics
python serve.py        # Windows
python3 serve.py       # macOS

serve.py starts a small local web server and opens this site in your browser. It uses only the standard library, so there is nothing to install for it. Stop it with Ctrl C. If port 8000 is taken, it picks the next free one and says so.

Then open the folder in VS Code: File → Open Folder and choose python-course-basics. The folder, not a single file. That is what makes the terminal start in the right place.

Not every session has every folder

Session 5 is git, so it is mostly terminal work and has no solutions/. Sessions 6 and 7 are SQL, so their demos and exercises are .sql files. Session 12 adds worksheets/ for the presentation and review. The session's README.md lists exactly what is there.

The dataset is one personal music listening log: 2,183 plays across 40 artists, from January 2024 to December 2025. You meet it properly in session 4, and it stays for the rest of the course. See the dataset page for every table and column.

How the work is organised

Notebooks are where the work happens

Each session has a notebooks/ folder. Open the notebooks in VS Code, or run jupyter lab from the repo folder. The file name tells you what a notebook is for.

Name ends inWhat it isExample
no suffixA walkthrough. You run it and change it during the session 01-first-steps.ipynb
-exerciseThe live exercise. Yours to fill in 02-about-me-exercise.ipynb
-homeworkHomework. Yours to fill in 03-statistics-homework.ipynb
-solvedThe answers, for after you have tried 02-about-me-solved.ipynb
-stretch-exercise, -stretch-solvedOptional extras, for when a session runs fast or you want more 04-stretch-exercise.ipynb

Everything also exists as a plain script

The same material lives in demos/, exercises/ and homework/ as .py files. That is on purpose. A notebook is for exploring; a script is for running. Seeing both is how the difference makes sense, and session 10 is about turning one into the other.

Anything that asks questions with input(), like the session 2 guessing game, is a script only, because input() is awkward in a notebook.

Run scripts from the repo root

Scripts find the data with paths like data/clean/plays.csv, which are counted from the folder your terminal is in. So run them from the top of the repo:

python sessions/session-04/demos/files_and_csv.py      # Windows
python3 sessions/session-04/demos/files_and_csv.py     # macOS

Run from anywhere else and you get a FileNotFoundError, even though the file is right there. Session 10 fixes this properly by building paths from the script's own location. Notebooks do not have the problem: each one starts with a cell that finds the repo root by itself.

Try it before you read the answer

The solutions are in the repo because you will want them later. Reading one feels like learning but is not, so have a real go first. Getting stuck for ten minutes is the part that sticks.

my-work/ is yours to make a mess in. Nothing in there is ever graded or checked.

A normal week

The session

Two hours, one to one. You share your screen and do the typing. Most sessions open with your homework, because where you got stuck is the best place to start.

The homework

Two to four hours, usually two tasks. One you can definitely finish, one you probably cannot. The second one is where the learning is. Each session's homework/README.md has the tasks.

If you get stuck, send the code and the exact error text, any time. Spend ten minutes reading the message first, because that is the skill. Do not spend an hour.

The Saturday line

One message, every Saturday, exactly one of these:

Homework done
Homework not done

No explanation needed. "Not done" is a perfectly good answer. It exists so the next session can be adjusted, not to check up on you, and it only works if it is cheap to send.

From session 5: commit and push

In session 5 your copy of the repo gets your own GitHub repo as origin, and the course repo becomes a second remote called course. From then on every session ends with a commit and a push.

git push                 # your work, to your repo
git pull course main     # updates to the course

Before session 5, if the course changes, you will be walked through a plain git pull at the time.

The shape of the twelve sessions

Python, then git, then SQL, then data, then your own project

  • 1 to 4, Python. Variables, control flow, functions, lists, dictionaries and files. Session 4 is where the dataset arrives.
  • 5, Git. Your own repo on GitHub, and enough understanding that git stops being frightening.
  • 6 and 7, SQL. Questions asked of data/music.db, first in DB Browser for SQLite, then from Python.
  • 8 and 9, pandas and matplotlib. The same questions in Python, then a deliberately messy file cleaned and turned into a chart.
  • 10 to 12, your project. A pipeline script in its own environment, a question of your own, and a presentation with a code review.
