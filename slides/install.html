1 · Python

Pick Python 3.12

Anything from 3.10 up runs the course code. The one catch is the project in session 10: project/requirements.txt pins matplotlib==3.9.0, and that version only has ready-made installers up to Python 3.12. On 3.13 or newer, pip tries to build it from source in session 10 and fails. So take 3.12 now and avoid the problem.

On python.org, go to Downloads, choose your system, and pick the newest 3.12 release that offers an installer (3.12.10).

Windows
  1. Download the Windows installer (64-bit) and run it.
  2. On the first screen, tick "Add python.exe to PATH". It is unticked by default. Miss it and the terminal will claim Python is not installed.
  3. Click Install Now.
macOS
  1. Download the macOS installer (the .pkg) and run it with the defaults.
  2. From now on, type python3 and pip3, not python and pip. That is the rule on a Mac for the whole course, until a virtual environment is active in session 10.

2 · VS Code

The editor, and two extensions

  1. Download VS Code from code.visualstudio.com and install it with the defaults.
  2. Open the Extensions panel (the four squares on the left) and install Python and Jupyter, both published by Microsoft. Python gives you the play button and error highlighting; Jupyter lets VS Code open notebooks.

The terminal inside VS Code opens with Ctrl ` on Windows and Cmd ` on a Mac. On Windows it is PowerShell. Use it for everything on this page.

macOS

To be able to type code . in a terminal: in VS Code, press Cmd Shift P and run Shell Command: Install 'code' command in PATH. Optional; File → Open Folder does the same job.

3 · Git

Install it now, even though it is explained in session 5

You need it today to copy the course to your machine, and the download is slow on some connections.

Windows

Download Git for Windows from git-scm.com and click through the installer with the defaults.

macOS

Type git --version in Terminal. If Git is missing, macOS offers to install the command line developer tools, which include it. Say yes, wait, and run git --version again.

4 · Prove each one is there

Close every terminal first, then open a new one

A terminal reads PATH only when it starts, so one that was open during the install cannot see what you just installed.

Windows 
python --version
python -m pip --version
git --version
macOS 
python3 --version
python3 -m pip --version
git --version

Good looks like Python 3.12.10, a pip line that ends in (python 3.12), and git version 2.something. The pip line names the Python it belongs to. If that is not the Python from the first line, see two Pythons on one machine.

"Not recognized" or "command not found" means the tool is installed but the terminal cannot find it. On Windows that is almost always the PATH box: re-run the Python installer, choose Modify, and tick the option to add Python to the environment variables.

5 · Get the course onto your machine

Clone it, open the folder, start the site

In the terminal, go to a folder you will find again. cd Documents is fine. Avoid spaces and accented characters in the path; it saves pain later.

git clone https://github.com/SybrandWildeboer/python-course-basics.git
cd python-course-basics

Open it in VS Code with File → Open Folder and pick python-course-basics, or type code .. Open the folder, not a single file, so the terminal starts in the right place.

Then start the course site:

Windows 
python serve.py
macOS 
python3 serve.py

Your browser opens on the course index. Stop the server with Ctrl C. python serve.py --no-browser starts it without opening a window, and --port 9001 picks a different port.

If git clone asks for a username and password, it should not for a public repo. Do not debug it now: download the ZIP from the GitHub page instead, and it gets fixed properly in session 5.

6 · Notebooks

Install JupyterLab

Windows 
python -m pip install jupyterlab
macOS 
python3 -m pip install jupyterlab

The session 1 slides write this as pip install jupyterlab. Putting python -m in front does the same thing, with one guarantee: the package goes into the Python that python runs, not some other Python that happens to own the pip command.

Open your first notebook

  1. In VS Code, open sessions/session-01/notebooks/01-first-steps.ipynb.
  2. Top right, click Select Kernel, then Python Environments, and pick the Python 3.12 you installed. If VS Code offers to install ipykernel, say yes.
  3. Click the first cell and press Shift Enter. The answer appears under the cell.

Prefer the browser? Run jupyter lab in the terminal, from the repo folder. Same notebooks, same everything.

7 · DB Browser for SQLite, before session 6

A window into the database

Windows

Download the Windows installer from sqlitebrowser.org and run it.

macOS

Download the .dmg from sqlitebrowser.org and drag DB Browser for SQLite into Applications. With Homebrew, brew install --cask db-browser-for-sqlite does the same.

To check it: Open Database, choose data/music.db from the repo, and look for three tables: plays, artists and awards.

8 · pandas and matplotlib, before session 8

The two packages sessions 8 and 9 use

Windows 
python -m pip install pandas==2.3.1 matplotlib==3.9.0
macOS 
python3 -m pip install pandas==2.3.1 matplotlib==3.9.0

These are the exact versions project/requirements.txt pins, so what you learn on in sessions 8 and 9 is what the project runs on from session 10. It is also why the Python has to be 3.12 or older: on 3.13, pip has no ready-made matplotlib 3.9.0 and tries to build it, which fails (see step 1).

Notebooks run in the Python their kernel points at, so pick that same Python 3.12 as the kernel. If a notebook says No module named 'pandas', the kernel is a different Python from the one you installed into.

9 · The project environment, in session 10

A private set of packages for project/

You do this together in session 10. It is here so you can redo it on another machine. Open a terminal in the repo root.

Windows · PowerShell 
cd project
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
macOS 
cd project
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

When it is active, the prompt starts with (.venv). Inside it, python and pip mean the project's own copies on both systems. You activate it again in every new terminal; deactivate switches it off.

If PowerShell says running scripts is disabled, run this once and try again:

Set-ExecutionPolicy -Scope CurrentUser RemoteSigned

For project/notebooks/explore.ipynb, pick the .venv Python as the kernel. It does not have ipykernel yet, so VS Code offers to install it. Say yes.

10 · pytest, in session 12

Into the project's environment, with it active

python -m pip install pytest
python -m pytest --version

Then add pytest with its version to project/requirements.txt, so a fresh copy of the project gets it too. python -m pip freeze shows the exact version you got.
